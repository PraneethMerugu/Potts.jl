   before production consolidation.

   evidence, and arbitration primitives while keeping output-family semantics
   and schedules with their owning lowerings.
3. LW-4C2 made canonical topology construction and package-owned bounded
   workspace the normal preparation path.

   author-oriented inspection derived from the same authoritative facts,

The public lifecycle remains:

```julia
workplan = plan(work, topology; backend)
prepared = prepare(workplan, storage; workspace)
event = run!(prepared, submission)
wait(event)
```

No second lifecycle, new execution family, provider, scheduler, queue, stream,
native-event fiction, domain physics, solver, RNG, clock, checkpoint, or
transaction authority was introduced.

## Corrected-candidate remediations

The first LW-R2 review found issues that block reuse if left unresolved. They
were corrected without weakening admission:

- full-coverage independent routes now reject every zero lane before lowering,
  preventing the generated direct path from ever publishing to index zero;
- ordered sequence fingerprints now hash the ordered stage fingerprints rather
  than requiring unrelated stage topologies to be identical;
- sequence `show` is valid and regression tested;
- result diagnostics identify the exact port;
- fast floating-point `numerical_bound` is explicitly `:not_claimed`;
- CorePotts continuation compares the complete preserved state and descriptor
  state, while queue-capacity arithmetic is checked;
- KernelAbstractions 0.9's lack of portable GPU compile-only validation is
  represented honestly as selected-device compilation deferred to first run,
  with failure poisoning at the cumulative synchronization boundary;
- `LocalWorkValidationError` now exposes stable structured fields on high-value
  topology, result, binding, alias, submission, workspace, capability, and
  provider-failure paths; and
- performance witnesses now retain raw paired timings, allocation counts and
  bytes, launches, waits, transfers, submissions, drains, and explicit receipt
  scope; and
- provider wait, lease release, and lease-index methods are frozen during
  preparation and revalidated before launch after method-world changes;
  post-submission synchronization and reclamation run in the last admitted
  world so later method piracy cannot strand the cumulative tail; and
- CorePotts validates both public LocalWorksets entrypoints before every new
  claim submission, but settlement of an already admitted tail invokes the
  stored package-owned wait in that admitted world, so exact broad public
  method replacement cannot prevent mandatory synchronization or reclamation.

The pre-freeze usability decision table and scores are in
`lw4c-usability-maintainability-audit.md`. It explicitly declines a 10/10 claim
until real LW-5 adoption demonstrates substantially lower downstream glue.

## Preserved semantics and ownership

- KernelAbstractions owns backend-portable kernel launch and implicit ordering.
- LocalWorksets owns validated connectivity, output conflict semantics,
  bounded workspace, lifetime, central lowering, and inspection.
- CorePotts retains checkerboard orchestration, RNG addresses, Hamiltonian
  before/after views and canonical source-order folding, acceptance, dual-owner
  claim meaning, commit, settlement, lifecycle, and checkpoints.
- PottsToolkit retains symbolic/ModelingToolkit authoring and compilation.

Hamiltonian authors continue to use `HamiltonianTerm`, `Volume`,
`ContactEnergy`, `Elongation`, and registered external Hamiltonians.
`complete`/`mtkcompile` continue proving purity, domains, and bounded affected
anchors. LocalWorksets remains below compiled descriptor evaluation.

The asynchronous checkerboard contract is unchanged: no intermediate waits,
multiple MCSs queue on one lane, color-order generation is preallocated, every
launch receives an immutable scalar color argument, and settlement remains
CorePotts-owned.

## Exact bundle admission

The final qualification command must create a new, nonexistent output path:

```sh
julia --project=. benchmark/lw4_qualification.jl \
  --output=design/hardening/lw4-final-qualification-bundle
```

The driver must record:

- exact candidate, project, and manifest hashes;
- Julia, OS, CPU, backend, package, and real-Metal hardware identity;
- exact commands, exact exit statuses, raw logs, and serialized machine
  results;
- complete standalone LocalWorksets, CorePotts, and root suites;
- CPU and real-Metal cross-domain witnesses;
- raw paired performance samples, allocation counts/bytes, launch/wait/
  transfer/submission/drain counters, and workspace facts;
- proof that no candidate file changed during qualification; and
- five independent ballots plus one nonvoting chair memo against that exact
  bundle.

Only after the contradiction/red-team round may the bundle be sealed with the
driver's `--finalize` mode. P0/P1 findings, a failed command, a missing machine
result, candidate drift, or a failed controlled performance bound blocks
freeze. CUDA and ROCm remain unclaimed. Root-suite wall time is correctness
context only and is excluded from performance evidence, including the earlier
travel-affected run.

MethodOfLines input-field integration remains deferred exactly as documented.
Fresh LW-R2 passed the sealed candidate. The authoritative final record is
`lw4-final-qualification-bundle`, committed at `a65622a2`; LW-5 is open.
