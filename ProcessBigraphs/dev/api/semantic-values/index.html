Semantic values and identity API

Support level: supported internal beta.

Semantic identity answers whether two declarations mean the same thing, not whether their mutable runtime objects happen to share storage. Fingerprints are deterministic across sessions for admitted values and include the versions and parameters that affect behavior.

ProcessBigraphs.semantic_fingerprint — Function
semantic_fingerprint(model)

Return the stable identity of the high-level semantic authoring model. Scientific-family, canonical-IR, execution-plan, problem, run, and checkpoint identities remain separate contracts.

ProcessBigraphs.problem_fingerprint — Function
problem_fingerprint(problem)

Return the identity of a SimulationProblem, including its model, typed initial state, parameters, observations, interventions, horizon, and root seed. It is not a run or checkpoint identity.

ProcessBigraphs.origin_map — Function
origin_map(lowered_or_compiled)

Return deterministic provenance linking normalized or compiled elements to their high-level authoring declarations. Use this for diagnostics and audit traces rather than inspecting private lowering records.

Inspect schemas without reading representation fields

schema_at and schema_leaves are the complete supported inspection route. Do not read the concrete child-storage field of BranchSchema: that tuple is free to change without an API migration.

ProcessBigraphs.schema_at — Function
schema_at(schema, path)

Return the schema node addressed by a typed Path, failing when the path is absent or traverses through a leaf. This is the supported schema-inspection route; concrete BranchSchema fields are representation details.

ProcessBigraphs.schema_leaves — Function
schema_leaves(schema)

Return a deterministic tuple of Path => LeafSchema pairs for every leaf in a schema tree. Ordering is canonical and does not expose concrete branch storage.

mass_schema = schema_at(schema, path(:cell, :mass))
for (store_path, leaf) in schema_leaves(schema)
    @info "declared leaf" store_path leaf
end

Both accessors return immutable semantic values. Mutating a default value obtained elsewhere cannot alter a compiled model.
