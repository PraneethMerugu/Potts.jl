Parameters: @parameters

@parameters declares the numbers of a model with their defaults. Parameters can be changed per problem (remake(prob; p = [...])), per run (integ.ps[:T] = 5.0 in a callback) and per trajectory of an ensemble, without regenerating code.

FormMeaning
λ = 1.0a scalar
V₀ = 2A₀a default computed from other parameters
J[kind, kind] = [0 16; 16 2]a table indexed by two kinds (medium first)
V₀[kind] = [0.0, 40.0, 25.0]a table indexed by one kind (entries are numbers)
d[1:2] = [1.0, 0.5]a vector; its components are d_1, d_2
λ = 1.0, [unit = u"J"]a parameter with a unit (see below)
using Potts

@potts_model Params begin
    @kinds medium dark light
    @parameters begin
        A₀ = 20.0
        V_big = 2A₀                            # computed from A₀
        V₀[kind] = [0.0, 40.0, 20.0]
        λ = 1.0
        J[kind, kind] = [0 16 16; 16 2 11; 16 11 14]
        drift[1:2] = [0.5, 0.0]
    end
    @lattice Lattice((40, 40); neighborhood = Moore(1))
    @energy begin
        cells(dark, light) => λ * (volume - V₀[kind])^2
        contacts => J[kind, kind′]
    end
    @sweep Metropolis(; temperature = 10.0)
end

@named params = Params(; λ = 2.0)          # keyword: a new default
op = layout(Tiling((5, 5); region = (11:30, 11:30), kinds = [:dark, :light]), params)
prob = PottsProblem(params, op, (0, 10))
prob.p
PottsParameters(A₀ = 20.0, V_big = 40.0, V₀ = [0.0, 40.0, 20.0], λ = 2.0, J = [0.0 16.0 16.0; 16.0 2.0 11.0; 16.0 11.0 14.0], drift_1 = 0.5, drift_2 = 0.0)

prob.p holds the values. Read one with getp(prob, :λ)(prob); change them with remake, by name or by symbol:

prob2 = remake(prob; p = [:λ => 5.0, :J => [0 16 16; 16 2 14; 16 14 14]])
getp(prob2, :λ)(prob2), getp(prob2, :J)(prob2)[2, 3]
(5.0, 14.0)

A computed default such as V_big = 2A₀ follows its inputs: remake with a new A₀ also changes V_big.

prob3 = remake(prob; p = [:A₀ => 30.0])
getp(prob3, :V_big)(prob3)
60.0

Values are converted to the problem's number type (Float64, or Float32 for GPU problems), so a remake never changes the compiled code.

Units

Parameters, variables and fields can carry units as ModelingToolkit metadata, λ = 1.0, [unit = u"J"]. When the package DynamicQuantities is loaded, compiling the model checks that every energy term, update and equation is dimensionally consistent. Built-in quantities (volume, surface, distances) are in lattice units. Without DynamicQuantities the units are ignored.
